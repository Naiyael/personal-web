# Knapsack

## 💡 核心思路
这题比普通背包多了一个“任选 $k$ 件免费拿”的机制。破题点在于先证明最优方案一定存在一个重量分界点：分界点左边负责挑免费物品，分界点右边负责正常做背包；于是原题被拆成“前缀维护前 $k$ 大价值”和“后缀做 $0/1$ 背包”两部分。

## 🛠️ 算法与数据结构
- **主要算法**：排序 + 优先队列维护前缀前 $k$ 大 + 后缀 $0/1$ 背包
- **时间复杂度**：$O(nW + n \log k)$，后缀背包主导
- **空间复杂度**：$O(W + n)$

## 🧠 核心推导 / 状态转移
先按重量 $w_i$ 从大到小排序。设某件物品 $a$ 被免费拿走，某件物品 $b$ 被付费买下，则必有：

$$
w_a \ge w_b
$$

否则交换二者的身份不会更差。

同时，若 $a$ 被免费拿走而 $b$ 完全没选，则必有：

$$
v_a \ge v_b
$$

否则把免费名额从 $a$ 换成 $b$ 更优。

由此推出：一定存在一个分界点 $M$，使得：

- 前缀 $[1,M]$ 中价值前 $k$ 大的物品被免费拿走
- 后缀 $(M,n]$ 中的一部分物品按背包容量 $W$ 正常购买

### 1. 后缀背包

设 `dp[j]` 表示当前后缀中花费不超过 $j$ 时的最大总价值，则标准转移为：

$$
dp[j] = \max(dp[j],\ dp[j-w_i] + v_i)
$$

代码从后往前扫，记录：

$$
a[i] = \text{仅使用后缀 }(i,n]\text{ 做背包时的最优值}
$$

### 2. 前缀免费物品

若当前把第 $i$ 件视作“最后一件免费物品”，那么其余免费物品只能从前缀 $[1,i-1]$ 里选，并且应当取其中价值最大的 $k-1$ 件。用一个小根堆维护这 $k-1$ 大值之和 `sum` 即可。

因此以 $i$ 为最后免费物品时，答案候选为：

$$
\text{sum} + v_i + a[i]
$$

再额外补一个“所有选择都来自免费物品”的情况，也就是直接取全局前 $\min(k,n)$ 大价值。

## ⚠️ 避坑指南 (Edge Cases)
分界点不是“前缀全拿”，而是“前缀里只拿价值前 $k$ 大作为免费物品”。
后缀背包数组 `a[i]` 必须在加入第 $i$ 件之前记录，否则会把本应免费拿的物品错误地放进付费背包里。
`k=0` 时退化成普通 $0/1$ 背包，代码单独特判。

## 📝 核心代码片段
```cpp
for (int i = n; i >= 1; i--) {
    a[i] = dp[w]; // 后缀 (i, n] 的最优背包值
    for (int j = w; j >= gems[i].first; j--) {
        dp[j] = max(dp[j], dp[j - gems[i].first] + gems[i].second);
    }
}

for (int i = 1; i <= n; i++) {
    if (i >= k) {
        ans = max(ans, sum + gems[i].second + a[i]);
    }
    pq.push(gems[i].second);
    sum += gems[i].second;
    if (pq.size() > k - 1) {
        sum -= pq.top();
        pq.pop();
    }
}
```
