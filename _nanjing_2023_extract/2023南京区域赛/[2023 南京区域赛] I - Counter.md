# Counter

## 💡 核心思路
一次 `c` 操作会把计数器直接清零，所以若在第 $a_i$ 次操作后数值为 $b_i$，那么最近一次清零的位置其实已经被这个条件强烈约束了。把所有已知条件按时间排序后，只需要逐段判断相邻两条记录之间是否存在合法操作序列。

## 🛠️ 算法与数据结构
- **主要算法**：排序 + 相邻约束判定
- **时间复杂度**：$O(m \log m)$，主要是排序
- **空间复杂度**：$O(m)$

## 🧠 核心推导 / 状态转移
设相邻两条已知条件为：

$$
(x_1, v_1),\quad (x_2, v_2),\quad x_1 < x_2
$$

中间一共有：

$$
\text{need} = x_2 - x_1
$$

次操作。

从 $(x_1,v_1)$ 走到 $(x_2,v_2)$，只有两种可能：

### 1. 中间没有清零

那么只能一直按 `+`，因此必须满足：

$$
v_2 = v_1 + \text{need}
$$

### 2. 中间至少有一次清零

设最后一次清零发生在区间内部某一步，那么从那之后只能连续按 `+` 到结尾，因此结尾值只取决于“清零后剩了几步”。

因为最后一次清零不能发生在第 $x_2$ 步之后，所以最终值最多是：

$$
\text{need} - 1
$$

也就是说，只要：

$$
v_2 \le \text{need} - 1
$$

就总能把最后一次清零安排在第 $x_2 - v_2$ 步，从而构造出合法方案。

因此每一段只需检查：

$$
v_2 = v_1 + \text{need}
\quad \text{或} \quad
v_2 \le \text{need} - 1
$$

全部区间都合法，整组数据就合法。代码把初始状态 $(0,0)$ 也当作一条已知条件一起判。

## ⚠️ 避坑指南 (Edge Cases)
若只判断 `v_2 <= need` 会错，因为一旦中间发生过清零，最后一次清零至少要占掉一步，所以最大只能到 `need - 1`。
必须把初始状态 $(0,0)$ 插进去，否则第一段约束会漏判。
题目里的总操作次数 $n$ 很大，但判定只依赖已知条件之间的相对关系，不需要真的模拟长度为 $n$ 的序列。

## 📝 核心代码片段
```cpp
sort(a.begin(), a.end());

for (int i = 1; i <= m; i++) {
    int need = a[i].first - a[i - 1].first;
    int cnt1 = a[i - 1].second;
    int cnt2 = a[i].second;

    if (cnt2 == cnt1 + need) continue;   // 中间没有清零
    if (cnt2 <= need - 1) continue;      // 中间至少一次清零

    flag = false;
    break;
}
```
