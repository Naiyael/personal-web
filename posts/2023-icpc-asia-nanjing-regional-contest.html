Primitive Root

# ICPC # Algorithm # C++
Problem Link

Core Idea

Rewrite the condition into the form g = (kP + 1) xor (P - 1). The point is not to enumerate all k, but to use bounds of xor so that only a constant number of boundary candidates need to be checked.

Algorithm and Complexity

  • Math transformation
  • Xor range bounding
  • O(1) time, O(1) space

Derivation

  1. Let g xor (P - 1) = kP + 1, then g = (kP + 1) xor (P - 1).
  2. Use the inequality a - b <= a xor b <= a + b with a = kP + 1 and b = P - 1.
  3. This gives a full valid prefix, a full invalid suffix, and only two boundary values of k that need direct checking.

Pitfalls

  • Do not brute force k; both P and m can be very large.
  • The target is g <= m, not kP + 1 <= m.
  • P = 2 still follows the same reasoning.

Code Snippet

long long ans = m / p;     // The full prefix is always valid
long long k1 = m / p;

if (((k1 * p + 1) ^ (p - 1)) <= m) {
  ans++;
}

long long k2 = m / p + 1; // Check the neighboring boundary candidate
if (((k2 * p + 1) ^ (p - 1)) <= m) {
  ans++;
}

cout << ans << '\n';

Knapsack

# ICPC # Algorithm # C++
Problem Link

Core Idea

The free-pick mechanism can be separated from the paid knapsack part. After sorting by weight, the optimal solution has a split point: the prefix contributes free items, and the suffix contributes ordinary 0/1 knapsack transitions.

Algorithm and Complexity

  • Sort by weight
  • Maintain the best prefix values with a min-heap
  • Run suffix 0/1 knapsack
  • O(nW + n log k) time, O(W + n) space

Derivation

  1. Sort all gems by weight in descending order.
  2. Build a[i] from the back, where a[i] means the best ordinary knapsack value using only suffix (i, n].
  3. Scan from left to right and use a heap to keep the best k - 1 values in the prefix. Treat the current item as the last free one and combine prefix sum + current value + suffix answer.

Pitfalls

  • The split point does not mean “take the whole prefix for free”. Only the top-value free candidates matter.
  • Record a[i] before inserting item i into the suffix knapsack.
  • Watch the boundary when k = 0.

Code Snippet

for (int i = n; i >= 1; i--) {
  a[i] = dp[w];
  for (int j = w; j >= gems[i].first; j--) {
    dp[j] = max(dp[j], dp[j - gems[i].first] + gems[i].second);
  }
}

for (int i = 1; i <= n; i++) {
  if (i >= k) {
    ans = max(ans, sum + gems[i].second + a[i]);
  }
  pq.push(gems[i].second);
  sum += gems[i].second;
  if (pq.size() > k - 1) {
    sum -= pq.top();
    pq.pop();
  }
}

Counter

# ICPC # Algorithm # C++
Problem Link

Core Idea

Each reset operation forces the later value pattern very hard. After sorting all known records by time, the problem reduces to checking whether every adjacent pair can be connected by some valid operation sequence.

Algorithm and Complexity

  • Sort known observations
  • Check adjacent constraints only
  • O(m log m) time, O(m) space

Derivation

  1. For adjacent records (x1, v1) and (x2, v2), define need = x2 - x1.
  2. If there is no reset in between, we must have v2 = v1 + need.
  3. If there is at least one reset in between, then the last reset leaves at most need - 1 increments to the end, so we need v2 <= need - 1.

Pitfalls

  • It is not enough to check v2 <= need; the reset itself consumes one step.
  • Insert the initial state (0, 0) before checking pairs.
  • No full simulation over all n operations is needed.

Code Snippet

sort(a.begin(), a.end());

for (int i = 1; i <= m; i++) {
  int need = a[i].first - a[i - 1].first;
  int cnt1 = a[i - 1].second;
  int cnt2 = a[i].second;

  if (cnt2 == cnt1 + need) continue;
  if (cnt2 <= need - 1) continue;
  flag = false;
  break;
}
